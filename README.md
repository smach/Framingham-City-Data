# Framingham City Data (Unofficial)

Data about Framingham, Massachusetts — mostly **election results by precinct**, plus precinct and district maps, property records and Census data — in both their **original form** and an **analysis-friendly form**.

**Website, with a searchable list of every file:** <https://smach.github.io/Framingham-City-Data/>

## Using the data

All election results are in one tidy file, one row per election × race × candidate × precinct:

```r
results <- readr::read_csv("https://raw.githubusercontent.com/smach/Framingham-City-Data/main/data/elections/results_precinct.csv")
```

| File | What's in it |
|---|---|
| `data/elections/results_precinct.csv` | Every election's results by precinct |
| `data/elections/results_district.csv` | The same, added up by city council district |
| `data/elections/turnout_precinct.csv` / `turnout_district.csv` / `turnout_citywide.csv` | Registered voters, ballots cast and turnout % (always 0–100) |
| `data/elections/by_election/` | One file per election laid out like the clerk's table, for reading in Excel |
| `data/elections/elections.csv` | The list of elections, including ones still to collect |
| `data/gis/framingham_precincts.gpkg` | Precinct boundaries for both precinct maps, with city council districts |

The website explains every column. One thing to know: precincts were redrawn in 2022 (18 → 27 precincts), so precinct "4" in 2021 and precinct "4" in 2023 are different places. The `city_district` column is always correct for the election date.

## How the project is organized

```
data-raw/            original files, never edited
  elections/
    elections.csv    THE REGISTRY: one row per election, where its files are, how to read them
    2023-11-07_municipal_general/   one folder per election: clerk PDF + spreadsheet converted from it
  lookups/precinct_districts.csv    which district each precinct is in, for each precinct map
data/                analysis-friendly files, all generated by code -- never edit by hand
  elections/  gis/  property/  census/  legacy/ (old files, kept for comparison)
R/                   functions only (load them all with source("R/load.R"))
scripts/             things you run: build_all.R, add_election.R, build_gis.R, update_property.R
tests/               automatic tests (Rscript tests/testthat.R)
index.qmd, _quarto.yml   the website source (Quarto); `quarto render` writes it to docs/
docs/                the rendered website, served by GitHub Pages -- don't edit by hand
.github/workflows/   automation (see below)
```


## Adding an election

**Convert the clerk's results PDF to Excel by hand in Adobe Acrobat** (export it to an Excel workbook). Don't use an AI model or another converter. Acrobat is reliable for PDFs the clerk made from Excel, which is most of them. Scanned PDFs are different: Acrobat has to OCR them, and the results come out with misread numbers (the September 2024 primary scan had about 17% bad cells). For a scan, ask the clerk for the original spreadsheet, or check every row against the validation report.

Then add it, with the spreadsheet, the status and the PDF:

```
Rscript scripts/add_election.R 2025-11-04_municipal_general ~/Downloads/results.xlsx unofficial ~/Downloads/results.pdf
```

That copies both files into `data-raw/elections/<id>/`, updates the registry, rebuilds the data and prints the validation checks. If one fails, the detail says which race and precinct don't add up: compare with the PDF, fix the spreadsheet, and run `Rscript scripts/build_all.R` again. When official results replace unofficial ones, run the same command with the official files and `official`.

From R you can also record the PDF's web address, so the weekly check knows it's been collected: `add_election(id, xlsx, status, pdf = ..., source_url = ...)`.

## Common tasks

**Rebuild everything** after changing raw data, the registry or the code:

```
Rscript scripts/build_all.R      # takes a few seconds
Rscript tests/testthat.R
```

**Property data** (MassGIS parcels and assessments) isn't stored in the repo, because each year's files come to about 20 MB. Run `Rscript scripts/update_property.R` to download the latest and write `data/property/assessments_fy<YEAR>.csv` (one row per property: values, use code, lot size, year built, owner, last sale) and `data/property/parcels_fy<YEAR>.gpkg` (boundaries; join on `LOC_ID`). MassGIS keeps only the latest year, so keep your own copies if you want a history.

**Census data:** `data/census/` has 2019–2023 American Community Survey estimates for the city and its 47 block groups (estimate and margin-of-error columns). When the Census Bureau releases a newer 5-year period, set a Census API key (see `R/census.R`) and run `source("R/load.R"); fetch_acs_framingham(<last year of the period>)`.

**Map:** `source("R/load.R"); make_precinct_map("2023-11-07", show_house_districts = TRUE)`

**Website:** edit `index.qmd`, then run `quarto render` in a terminal from the project folder (or use RStudio's Render button). The searchable file list builds itself from every file committed under `data/` and `data-raw/`. Files that exist only on your computer are left out. A new kind of file shows up without a description until you add a matching row to `data-raw/catalog_descriptions.csv`.

## Automation

Three GitHub Actions in `.github/workflows/`:

* **check-elections.yml** runs every Wednesday. It looks for new results on the City Clerk's page and, if there are any, **opens a GitHub issue** listing them with the `add_election()` line to run after you convert each one in Acrobat. It changes nothing in the repository and doesn't open a second issue while one is open. No setup needed.
* **test.yml** runs on every pull request. It rebuilds the data, fails if a validation check fails or if the committed data doesn't match the code, and runs the tests.
* **build-site.yml** re-renders the website with Quarto when something changes on `main`, and commits the result to `docs/`.

## Data sources

* Election results: Framingham City Clerk (results PDFs). Spreadsheets for older elections were converted from PDFs with CometDocs or PDFTables; from 2024 on, with Adobe Acrobat. Every election passes automatic checks (precinct numbers add up to the clerk's totals, ballots ≤ registered voters, and others); see `data/elections/validation_report.csv`.
* Precinct maps: Framingham GIS. State House districts: the Legislature's 2021 redistricting plan. Block groups: US Census Bureau.
* Property: Framingham Open Data (2017–2018 files); MassGIS standardized assessors' parcels going forward.

The scripts that made the original files before the 2026 rebuild are in the git history (commit `2a8ca16`).
