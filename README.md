# Framingham City Data (Unofficial)

Data about Framingham, Massachusetts — mostly **election results by precinct**, plus precinct and district maps, property records and Census data — in both their **original form** and an **analysis-friendly form**.

**Website, with a searchable list of every file:** <https://smach.github.io/Framingham-City-Data/>

## Using the data

All election results are in one tidy file, one row per election × race × candidate × precinct:

```r
results <- readr::read_csv("https://raw.githubusercontent.com/smach/Framingham-City-Data/main/data/elections/results_precinct.csv")
```

| File | What's in it |
|---|---|
| `data/elections/results_precinct.csv` | Every election's results by precinct |
| `data/elections/results_district.csv` | The same, added up by city council district |
| `data/elections/turnout_precinct.csv` / `turnout_district.csv` / `turnout_citywide.csv` | Registered voters, ballots cast and turnout % (always 0–100) |
| `data/elections/by_election/` | One file per election laid out like the clerk's table, for reading in Excel |
| `data/elections/elections.csv` | The list of elections, including ones still to collect |
| `data/gis/framingham_precincts.gpkg` | Precinct boundaries for both precinct maps, with city council districts |

The website explains every column. One thing to know: precincts were redrawn in 2022 (18 → 27 precincts), so precinct "4" in 2021 and precinct "4" in 2023 are different places. The `city_district` column is always correct for the election date.

## How the project is organized

```
data-raw/            original files, never edited
  elections/
    elections.csv    THE REGISTRY: one row per election, where its files are, how to read them
    2023-11-07_municipal_general/   one folder per election: clerk PDF + spreadsheet or extracted.csv
  lookups/precinct_districts.csv    which district each precinct is in, for each precinct map
data/                analysis-friendly files, all generated by code -- never edit by hand
  elections/  gis/  property/  census/  legacy/ (old files, kept for comparison)
R/                   functions only (load them all with source("R/load.R"))
scripts/             things you run: build_all.R, add_election.R, build_gis.R, update_property.R
tests/               automatic tests (Rscript tests/testthat.R)
index.qmd, _quarto.yml   the website source (Quarto); `quarto render` writes it to docs/
docs/                the rendered website, served by GitHub Pages -- don't edit by hand
.github/workflows/   automation (see below)
```

## Setup (once)

In R, from the project folder:

```r
install.packages("pak")
pak::local_install_deps(dependencies = TRUE)   # installs everything listed in DESCRIPTION
```

For Claude PDF extraction, add your Anthropic API key to `~/.Renviron` (run `usethis::edit_r_environ()`), as `ANTHROPIC_API_KEY=...`, then restart R.

## Common tasks

**Add an election from a clerk PDF** (Claude reads the PDF; the numbers are then checked automatically):

```
Rscript scripts/add_election.R 2025-11-04_municipal_general ~/Downloads/results.pdf unofficial
```

It prints the validation checks. If one fails, the detail says which race and precinct don't add up: compare with the PDF, fix `data-raw/elections/<id>/extracted.csv` (a plain CSV), and run `Rscript scripts/build_all.R` again. When official results replace unofficial ones, run the same command with the official PDF and `official`.

**Rebuild everything** after changing raw data, the registry or the code:

```
Rscript scripts/build_all.R      # takes a few seconds
Rscript tests/testthat.R
```

**Update property data** (about once a year): `Rscript scripts/update_property.R`

**Census data:** `fetch_acs_framingham(2023)` after setting a Census API key (see `R/census.R`).

**Map:** `source("R/load.R"); make_precinct_map("2023-11-07", show_house_districts = TRUE)`

**Website:** edit `index.qmd`, then run `quarto render` in a terminal from the project folder (or use RStudio's Render button). To describe a new kind of file in the site's file list, add a row to `data-raw/catalog_descriptions.csv`.

## Automation

Three GitHub Actions in `.github/workflows/`:

* **check-elections.yml** runs weekly, and daily in September–November. It looks for new results on the City Clerk's page, extracts and checks them, and **opens a pull request** for you to review. To turn it on: add an `ANTHROPIC_API_KEY` repository secret, and tick *Settings → Actions → General → Allow GitHub Actions to create and approve pull requests*.
* **test.yml** runs on every pull request. It rebuilds the data, fails if a validation check fails or if the committed data doesn't match the code, and runs the tests.
* **build-site.yml** re-renders the website with Quarto when something changes on `main`, and commits the result to `docs/`.

## Data sources

* Election results: Framingham City Clerk (results PDFs). Spreadsheets for older elections were converted from PDFs with CometDocs or PDFTables; newer ones are extracted with Claude via the ellmer R package. Every election passes automatic checks (precinct numbers add up to the clerk's totals, ballots ≤ registered voters, and others); see `data/elections/validation_report.csv`.
* Precinct maps: Framingham GIS. State House districts: the Legislature's 2021 redistricting plan. Block groups: US Census Bureau.
* Property: Framingham Open Data (2017–2018 files); MassGIS standardized assessors' parcels going forward.

The scripts that made the original files before the 2026 rebuild are in the git history (commit `2a8ca16`).
